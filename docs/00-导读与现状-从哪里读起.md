## 2. 三条最容易被忽略、但最重要的既有纪律

读规划时如果只记三件事，记这三条（它们解释了为什么很多任务是那样设计的）：

| # | 纪律 | 出处 | 含义 |
|:---|:---|:---|:---|
| **1** | **顺序即语义** | `spec.md` | 路由执行顺序是「隐私判定 → 预算闸门 → 意图匹配」，**反了就是漏洞**（意图先命中就会绕过隐私）。这条要求有测试，不靠代码走查 |
| **2** | **绿灯不代表你以为的那件事成立** | `tasks.md` FU-8 | 一半问题是**断言错了**（量纲对不上错误方向），另一半是**检查不承重**（去掉某步仍全绿）。所以每个 task 都配**负对照**与**变异测试** |
| **3** | **契约是资产，组件是耗材** | `06 §10` | 换 Router / 换模型 / 换后端都不该改调用方。`LoadPolicy`、`ProviderDescriptor` 这些抽象存在的唯一理由就是这条 |

## 5. Windows 兼容：范围决定成本（**新增待拍板项 W-1**）

> 背景：`architecture.md` 核心判断 3 已写「**不写死 oMLX**，按平台探测，`omlx` 字样只能出现在 `adapters/omlx/` 下」。
> 所以**架构上我们从未与 Apple 绑定**——但"Windows 用户能不能用"取决于你问的是哪一种。

### 5.1 两个完全不同的场景

| | **场景 A · Windows 作为客户端** | **场景 B · Windows 本地跑 iDoris** |
|:---|:---|:---|
| 谁在哪 | 服务跑在 Mac/Linux 上，Windows 只是个浏览器/CLI | 用户在自己 Windows PC 上装 iDoris |
| 需要什么 | **只需 HTTP** | Router 进程 + 推理后端 + 密钥库 + 出网控制，**全都要 Windows 实现** |
| 成本 | ✅ **几乎为零**（OpenAI-compat 本来就是 HTTP）| 🔴 **高**——是四块独立工作，不是一次编译 |
| 何时需要 | 泰国业务的多客户访问 | 有真实 Windows 用户要"数据不出本机" |

### 5.2 场景 B 具体要补什么

| 组件 | macOS | Windows 对应物 | 工作量 |
|:---|:---|:---|:---|
| **推理后端** | oMLX（MLX） | **GGUF/llama.cpp** 或 NVIDIA 上的 vLLM | 🟠 中（`LoadPolicy` 抽象已就位，但要真写适配器）|
| **密钥库**（闸二）| Keychain / Secure Enclave | **DPAPI / Credential Manager / Windows Hello** | 🔴 **高**——是完全独立的实现，不是换个 crate |
| **出网控制**（闸一/启动断言）| socket 打桩 | Windows Filtering Platform / 类似机制 | 🟠 中 |
| **子进程管理**（`T1.4.1` 无孤儿）| `process_group()` + `kill_on_drop` | Job Objects（语义不同，要重写清理逻辑）| 🟠 中 |
| **守护进程形态** | LaunchAgent | Windows Service | 🟡 低 |

### 5.3 ⭐ 一个重要的汇合点

> **"支持 Windows"和"支持长上下文"指向同一件事：把 GGUF/llama.cpp 后端做成一等公民，而不是"以后再说"。**

调研已确证（[`14 §7.4`](./14-常驻服务技术栈选型-语言与推理后端.md)）：**MLX 的 `--kv-bits` 会禁用连续批处理**，所以**长上下文 / RAG / 高并发这个角色本来就必须走 llama.cpp**。

也就是说：**做 GGUF 适配器不是"为了 Windows 的额外成本"，而是本来就该做的第二后端。** 它同时解锁三件事——Windows、长上下文、跨平台。

**建议 W-1 的选项：**

| 选项 | 含义 | 建议 |
|:---|:---|:---|
| **W-1a** | 只做场景 A（客户端兼容），服务端先 Mac/Linux | ✅ **M1 阶段的正确答案** |
| **W-1b** | A + **提前做 GGUF 适配器**（反正长上下文要用）| ✅ **推荐**——一举两得 |
| **W-1c** | 完整场景 B（含 Windows 密钥库 + 出网控制 + Job Objects）| ⏳ 等有真实 Windows 用户再评估 |
