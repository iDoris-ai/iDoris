## 1. 结论

**没有任何开源项目能直接拿来做 iDoris 的基础。** iDoris 有三项刚需：
- ① 单二进制 + SQLite；
- ② 按隐私 → 预算 → 意图的顺序做确定性、fail-closed 的准入链；
- ③ 本地运行时的生命周期管理。

每个候选最多只覆盖其中一两项，第 ③ 项**所有网关都没有**。

**建议（D-R1 选 C）**：自建一个精简的 Rust 策略内核，分层借鉴业内最好的实现。以 agentgateway 为主要设计参照；出站 provider 客户端直接依赖 `genai` crate。以后组织版如果客户已经在用 agentgateway，iDoris 再作为它的 ext_proc 策略服务接入（M8 再议），不把它放进个人版的主链路。

## 2. 候选排名（只列通过许可证审查的）

| 名次 | 项目 | 许可证 | 定位 | 为什么不直接用 |
|:---|:---|:---|:---|:---|
| 1 | **agentgateway**（Linux Foundation，Solo.io 主导，约 189K 行） | Apache-2.0 | 工程质量与活跃度全场最高；**唯一**同时具备 SQLite 默认存储、真实金额预算、默认 fail-closed 的 guardrail、可写 Admin API、CEL 路由、ext_proc/ext_authz 扩展点的候选 | 策略顺序写死为"鉴权 → 预算 → 外部裁决"，没有隐私步骤；预算是"先查后记"，非原子；**价格未知时不计费**；多目标负载均衡是 `rand` 加权随机；没有运行时管理；单体 crate 无法拆开，依赖 AWS SDK 和 k8s 全家桶 |
| 2 | **aisix**（API7，18 个 crate） | Apache-2.0 | 代码质量最高（496 个 e2e 用例）；虚拟 key、11 种 PII 检测器、6 种路由策略、cooldown 都已到生产级 | 开源版**没有本地预算**（依赖付费云端）、没有运行时管理、Admin API 只读、没有 SQLite |
| 3 | **plano**（原 archgw） | Apache-2.0 | 路由决策可解释性、多 provider 转换、OTel 做得好 | 意图判定是一次大模型调用，解析失败时 **fail-open**；PII 与越狱护栏是死代码；没有 key、预算和 Admin |
| 专项 | **llamastash** | MIT（README 另附"禁军用"声明） | **本地运行时管理的最佳参照**：状态机、健康探针、空闲驱逐、单飞、端口冲突处理 | 不支持 MLX；只借鉴设计，不照抄代码（许可证附加声明的效力存疑） |
| 专项 | **mistral.rs** | MIT | `/v1/models` 与 load/unload/reload/status 生命周期 API 是最好的协议参照 | 本身是推理引擎，不是网关 |
| 专项 | **genai** crate | MIT/Apache-2.0 | 自带 **oMLX adapter**，另有通用 OpenAI 兼容机制，出站客户端首选 | 单一维护者，0.7 还在 beta，需要用我们自己的 trait 隔离 |

**一票否决**：
- Helicone：已改为 GPL-3.0。
- LangDB/vllora：Elastic License，含"不得作为托管服务提供"条款。
- TensorZero：约 47 万行；只支持 ClickHouse/Postgres，没有 SQLite；3.5 个月没有代码推送。
- NVIDIA llm-router：实测是 Python。
- Agent Router（原 Envoy AI Gateway）：是 Go 写的。

**方向信号**：LiteLLM 正在把核心重写成 Rust（`litellm-rust`，40 多个 crate）。它的 crate 切分方式（router/auth/cache/cost/gateway/token-counter）和我们的设想几乎一样，但目前是通过 PyO3 嵌在 Python 里运行，不是独立二进制，所以不能用。建议每季度看一次。

## 3. 三条路径的对比（D-R1）

| 路径 | 做法 | 工作量 | 与不变式的冲突 | 判断 |
|:---|:---|:---|:---|:---|
| A. fork agentgateway | 在它的主链路里改成我们的策略链 | 6–10 人周（报告估算，按人力计） | #14（fork 189K 行等于 vendor 第三方源码）；上游约每天 11 个提交，同步成本不可控 | ❌ |
| B. agentgateway 做前置数据面，iDoris 策略作为 ext_proc 服务 | 两个进程，经 gRPC 协作 | 3–5 人周 | 个人版变成两个进程，违背单二进制和"妈妈测试"；它自己的预算和随机负载均衡必须关掉，最后只剩协议转换、鉴权和 OTel，这些用 `genai` 加 axum 就能覆盖；多一跳，也多一个故障域；依赖图过大（供应链风险） | ⚠️ 留给组织版 |
| **C. 自建精简内核 + 分层借鉴** | 单二进制；策略链、预算、运行时管理自己实现；出站客户端依赖 `genai` | 与原 R2–R5 相当，用子 agent 并行约 1.5–2 周 | 无 | ✅ **推荐** |

**选 C 的根本原因**：iDoris 的价值恰恰在策略链的顺序和 fail-closed 语义，以及本地运行时管理，而这两块**没有任何项目实现**。别人能提供的部分（协议转换、鉴权、观测）很薄，用成熟 crate 就能拿到。

## 4. 重新设计要点（按层，都有出处）

在恢复 R0/R1 之前，先把这些写进总体规划 §4 和 R 系列任务。

**模型管理层（改动最大）**
- **单写者事件循环**：进程机制、调度策略、驱逐策略三者分离，驱逐决策写成**纯函数**，副作用只通过 Effects 接口发出。〔llama-swap `internal/router/design.md`；Issue #946 模型永久卡死的根因〕
- 运行时状态机：`Launching → Loading → Ready | Error → Stopping → Stopped`，外加健康探针、空闲驱逐、单飞合并。〔llamastash `supervisor.rs`、`probe.rs`、`coalesce.rs`、`eviction.rs`〕
- **加载与驱逐全局互斥，已加载的模型并发服务**；卸载后轮询确认资源真的释放了，超时则退回估算值；OOM 只自愈重试一次（熔断）。〔Ollama `server/sched.go`：`activeLoading`、`waitForVRAMRecovery`、`oomRetryAttempted`〕
- 手动、自动、API、CLI 所有加载路径汇入**同一个**决策点，不留旁路。〔LM Studio #2051〕
- 协议语义：`/v1/models` 列出"可路由"的模型，不论是否已加载，并标出 `status`。〔mistral.rs；LM Studio JIT〕
- 原来的 `ModelBackend` trait 下沉为"运行时适配器"，上面加一层 **Runtime Supervisor**（C-4 早已规划，现在有了具体范式可循）。

**路由与意图层**
- 按 **Filter → Score → Pick** 三段组织。Filter 内部按不变式 #1 的顺序执行：**隐私 → 意图/角色 → 预算（只作用于所选路径上的付费候选）→ admission**。（2026-09-27 订正：原文写的是「隐私和预算都在 Filter 里」，容易被理解成预算先于意图，这个说法已经被不变式 #1 的修订取代），每段都是纯函数；**禁止使用随机数**，要保证确定性。〔llm-d 调度器；agentgateway 负载均衡的反例〕
- 分类器只识别**意图类别**，类别到模型的映射放在可热更新的表里，新增模型不用重训。〔Arch-Router 论文〕
- 判定器失败时 **fail-closed**，或者按规则兜底并在响应里明示，**不能静默回落到客户端原始 model**。〔plano `orchestrator_model_v1.rs` 的反例〕
- 决策输出带 reason_code，并可回放。〔plano `session_router.rs`；semantic-router `pkg/decision`〕

**隐私层**
- **检测与处置分开**；每种实体类型可以单独插拔、单独验证召回率。〔Presidio；vLLM semantic-router #712〕
- **"没命中"和"检测器故障"是两种状态**：故障时 fail-closed。〔semantic-router #4271〕
- 工具调用的返回结果也要检测。〔semantic-router #3560〕
- 内置正则检测器（11 种，带 Luhn/ISO7064 校验）直接移植 aisix 的 `pii.rs`（Apache-2.0，保留署名）。

**预算层**
- **reserve 在准入阶段用 SQLite 事务原子扣减**，settle 阶段修正差额；只对成功的调用结算。〔LiteLLM #32614；agentgateway 的"先查后记"是反例〕
- "内存为准 + 定期 flush + 启动时预加载 + reconcile"这套骨架可以借鉴，但 reserve 必须原子。〔agentgateway `http/budget/`〕
- 预算作用域是 (tenant, key, provider, model) 四元组。〔Kong #3949〕
- **价格未知一律拒绝**（agentgateway 的做法是不计费，与我们的不变式 #3 冲突）。
- **token 估算不能用"字符数 ÷ 4"**：中文场景会少估 2–2.4 倍，必须用真实 tokenizer 或保守系数。〔blog：orion-core 实测〕

**审计与观测层**
- 审计在**响应返回之后异步写入**，管道故障不影响响应。〔Helicone〕
- 元数据与内容物理分层。〔Langfuse；aisix `SinkRecord`/`SinkContent`〕
- 字段采用 `gen_ai.*` 语义约定，并钉死版本。〔OpenLLMetry〕
- 可观测性开关分三档：`null`（尽力而为，失败时告警）、`true`（必须成功）、`false`（关闭）。〔TensorZero〕

**身份与管理面**
- 虚拟 key 的语义边界在设计阶段就写清楚：它只是凭证，还是凭证加路由策略。〔Portkey #1190〕
- **策略表达式用 CEL，不自造 DSL**（D-R2）。〔agentgateway、Bifrost；NeMo Colang 两代的教训〕
- 可写 Admin API 只能自研，因为 aisix 只读、plano 没有。形态参照 agentgateway 的 `config_store.rs`：进程内用 `watch` 通道热更新，所有入口读同一份已批准的版本化配置。〔LM Studio #1463〕
- 自定义 upstream/host 字段必须走白名单，防 SSRF。〔Portkey GHSA-hhh5-2cvx-vmfp〕
- **鉴权失败与依赖故障返回不同的错误，不能互相伪装**。〔OpenRouter 2026-02 故障〕
- 订阅和外部 API 的凭证不下发给上层。〔blog：OneCLI〕

**学习层**
- 只有**真正提交执行**的决策才写进轨迹；投机性重评估不写，以免污染训练分布。〔llama-swap 日志原则〕
- 路由模型做成独立的、可灰度的子服务。〔NVIDIA llm-router Controller/Server 分离〕
- 训练数据稀疏是常态，需要规则或强模型做半自动标注。〔RouteLLM 论文〕
