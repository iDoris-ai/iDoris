## 4. 逐篇笔记（原样保留，含「⇒ 借鉴」结论）

## L0 原点 · iDoris 立项思考（idoris-project-launch, 2026-04-27）
- 核心命题：本地 AI 持续学"我"但不交出原始数据；多用户少量数据隐私安全聚合；个人→社区→城市一条线生长。
- 三硬约束：算力(64GB Mac)/隐私(原始数据不出本机)/数据量(单人1-10GB) ⇒ PEFT(LoRA) + 权重可上传数据不出 + 分层。
- 知识四介质：基座(不变)/LoRA(周月,风格偏好领域)/RAG(秒级,新事实长尾)/DPO偏好集(持续,👍👎)。四者各管一段。
- 同基座(Qwen 家族)+分层LoRA叠加 W=W_base+Σα_i ΔW_i，α 由用户在 GUI 滑动 = "多信任社区/城市"。
- 隐私闸门：①PII脱敏(Presidio+中文NER) ②用户主题级授权(工作/生活/健康/财务) ③DP-SGD(ε≤8,δ≤1e-5) ④上传二次审计+异常剔除(Krum/Median) → FedAvg/SLoRA。
- **§9 关键：价值留在数据和方法里，不留在权重里**——RAG库/DPO偏好集/训练语料与基座无关(0-15%迁移成本)，只有LoRA权重100%绑定。⇒ 轨迹数据格式必须基座无关、tokenizer无关（存消息级结构，不存token ids）。
- 验收标准是主观"懂我程度"对比 Claude（3 个月不如就重审）。

## L3 · SemIf（OpenJev 开源复刻，MIT，3.7k★，2026-09-22）——入口判定层的直接参考实现
- 直接读 logit：state+question+options → 单次前向 → 选项 logit softmax → 概率分布；**0 输出 token**，比自回归 JSON 快 5.21×。
- **状态复用**：同一 state 多个判断标准，KV 只算一次、suffix 并行分叉（20 decisions/s，~50ms/次）。实验性：BF16 下 777 次里 5–6 次与全新评分不同。
- 准确率：Qwen3.5-4B 0.813 / Qwen3.8-27B 5bit 0.958；**校准后 ECE 降 44–67%**。
- 后端 CUDA / **MLX** / llama.cpp / WebGPU。
- **可审计输出**：每条决策带 model_revision(HF commit) + prompt_hash + latency，行级不聚合。
- ⇒ iDoris「入口判定层」设计：一个 state（请求摘要）× 多个 question（intent 选择 / privacy_class 选择 / complexity 选择 / needs_tools 判断）→ 一次前缀、并行出多个校准分布；每个决策记录 {model_revision, prompt_hash, scores, latency}——**这条记录本身同时是审计证据和训练样本**。准确率 4B 0.81 不够做隐私放宽决定 ⇒ **隐私只能让模型"收紧"不能"放宽"**（显式 header 与规则永远优先；模型判为敏感→升级为 local_only；判为不敏感→不改变默认 local_only）。

  1. **ATDP（Agent Trajectory Data Protocol）**：每步 `eₜ = ⟨oₜ 可观测状态, hₜ 隐含内部状态(规划/推理摘要/置信度), aₜ 动作(类型化工具调用/生成), yₜ 动作结果(工具返回/用户接受-编辑-删除), rₜ 奖励(二元/标量/自然语言), mₜ 元数据(延迟/token/成本/租户/Harness 版本)⟩`。四原则：**信用可归因**（完整决策上下文）/ **延迟绑定奖励**（下一轮纠正、测试失败、后置标注可补进已有轨迹）/ **版本化可回放**（harness 版本、工具 schema、检索索引快照、模型 checkpoint）/ **受治理的可观测性**（脱敏状态、数据分类标签、租户 ID、保留策略、**训练资格**——从捕获第一步内置）。
  2. **Agentic Data Proxy**：坐在 Agent 与 LLM 后端/工具/记忆/人类反馈之间，无侵入拦截；无损 ATDP 序列化、**回放能力（不是监控日志，是训练数据）**、**跨租户聚合 + 隔离**、**奖励收割**（用户回复/测试失败/人工纠正）、数据治理。"监控代理记录失败了；学习代理还要能回答换个 prompt/模型/检索会不会成功"。
  3. **Agent Evolution Control Plane**：按窗口内轨迹选演进动作 {更新权重 / 更新 in-context harness / 更新记忆 / 更新工具 schema / 回滚 / No-op}；自动触发条件：评估分数、用户纠正率、流程奖励估计、工具失败集群、金丝雀 delta、**每次成功任务的成本**。
- 原型架构：Gateway(OpenAI 兼容) → **Router(会话亲和)** → Data Proxy → Worker(SGLang/vLLM 推理 + Megatron/FSDP 训练)；接入只改 base_url。
- 决策指南：工具 schema 错→改 harness；窄窗口重复问题→写记忆(最便宜)；跨用户推理错→RL；金丝雀降→回滚；**单租户特有问题→隔离数据仅用该租户轨迹微调**。
- 低资源：GRPO+LoRA rank16。
- ⇒ **iDoris 轨迹方案以 ATDP 为骨架**（与 Agent24 已用的 ATIF 做字段映射，二者都是"步骤级、类型化、带元数据"）；iDoris Router = AReaL 图中的 Gateway+Router(会话亲和)+Data Proxy 三合一；**训练资格/分类标签/租户/保留策略在捕获时就写入**（不是事后补）；奖励延迟绑定 = `/v1/feedback` 可在任意时间补到 record 上；演进控制面的触发指标 = 管理 UI 的"学习"看板。租户数据只训租户自己的 adapter（与 T1.5.3 硬隔离同向）。

## WEB · 轨迹/训练格式标准核实
- **ATIF（Agent Trajectory Interchange Format，Harbor RFC 0001）当前 v1.8（2026-04）**：root `schema_version`(req, "ATIF-v1.8") / `session_id` / `trajectory_id` / `agent{name,version,model_name,tool_definitions,extra}`(req) / `steps[]`(req) / `final_metrics` / `continued_trajectory_ref` / `subagent_trajectories[]` / `extra`。Step：`step_id`(int,req,从1) / `timestamp` / `source`(system|user|agent, req) / `model_name` / `reasoning_effort` / `message`(req, text 或 ContentPart[]) / `reasoning_content` / `tool_calls[{tool_call_id,function_name,arguments}]` / `observation{results[{source_call_id,content,subagent_trajectory_ref}]}` / `metrics{prompt_tokens(含缓存),completion_tokens,cached_tokens,cost_usd,prompt_token_ids,completion_token_ids,logprobs}` / `llm_call_count`(0=确定性步骤) / **`is_copied_context`(true 必须从 SFT 排除)** / `extra`。多模态 ContentPart(text/image/audio by path)。Pydantic 参考实现 + `harbor.utils.trajectory_validator`。NVIDIA NeMo Agent Toolkit 内置 `nat.atif`；VT Code 等采用。
  - ⇒ **iDoris 轨迹交换格式 = ATIF v1.8**；AReaL ATDP 的治理字段（分类/租户/保留/训练资格/harness 版本/奖励）放入 `extra.idoris.*` 命名空间；Agent24 现行"ATIF"（DGM 风格 YAML）应对齐到 Harbor ATIF v1.8——这是跨仓库需求（写入 docs/09 对 Agent24 的需求）。
- **OTel GenAI 语义约定**：截至 2026-07 **全部仍是 Development（非 Stable）**；2026-06-12 v1.42.0 起迁到独立仓库 `open-telemetry/semantic-conventions-genai`；属性 `gen_ai.provider.name`(替代 gen_ai.system)、`gen_ai.request.model`/`response.model`、`gen_ai.usage.input_tokens`/`output_tokens`、`gen_ai.response.id`；内容用 `gen_ai.input.messages`/`output.messages`/`system_instructions` 属性（v1.37 起替代逐消息事件）；span：chat / invoke_agent / execute_tool / retrieval / plan。
  - ⇒ OTel 用于**运维遥测与审计导出（不含内容，内容属性默认关）**，并**版本钉死**（因非 stable，字段名会变）；ATIF 用于**内容级轨迹与训练**。两者通过 `gen_ai.response.id` ↔ ATIF `extra.idoris.record_id` 关联。
- **训练格式**：mlx-lm LoRA 接受 JSONL `chat{messages}` / `tools{messages,tools}` / `completions{prompt,completion}` / `text`，`train/valid/test.jsonl`，`--mask-prompt`；**mlx-lm 文档未提 DPO**。TRL：DPO `{prompt, chosen, rejected}`（支持对话格式）；**KTO 非配对 `{prompt, completion, label: bool}`**——👍/👎 天然是 KTO 格式；用户修正（corrected_output vs 原输出）天然是 DPO 对。

## WEB · 泰国 PDPA 对 AI 训练的要求（2026）
- PDPC 2026-02-17 发布《AI 开发与使用中的个人数据保护指南》草案（二稿已出）：**用户 prompt、向量 embedding、交互日志都属个人数据范围**（即便技术变换后，只要结合密钥/补充数据可识别个人）；**目的限制严格：为某目的收集的数据不得在无新合法依据时转用于模型训练；原依据是同意的，需重新同意**；DPA 应含**训练禁止条款，包括删除模型权重与向量库**。
- ⇒ **决定性设计约束**（也与中国 PIPL 目的限制同向）：①"记录轨迹"与"用轨迹训练"是**两个不同目的、两个独立开关**：`retention`（运维/审计/合规，按合同或合法利益，有保留期）与 `training_eligibility`（需要**单独的、可撤回的同意**或组织与其客户之间的 DPA 授权）；②轨迹是个人数据，按个人数据全生命周期管理（加密/最小化/保留期/删除权）；③**删除要能级联到 embedding 与 adapter 权重**（血缘表 → 受影响 adapter 标记撤回/重训）——PDPC 明确提到"删除模型权重与向量库"；④泰国业务（docs/12）的组织租户，默认 `training_eligibility=false`，由租户管理员在取得其客户同意后开启。
