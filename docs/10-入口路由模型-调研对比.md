# 入口路由模型 —— 全面调研与对比分析

> 文档类型：技术选型调研（GitHub + HuggingFace 命令检索 + web）
> 日期：2026-07-30 ｜ 维护者：iDoris.ai / @jhfnetboy
> 关联：[08 图4 入口路由](./08-架构图-生态蓝图.md) / [09 对Agent24需求](./09-对Agent24的需求.md)
>
> **需求界定**：一个 **入口小模型（~0.1B 量级）**，按用户输入**路由到解决方案** —— 纯 agent / web 搜索 / 发邮件 / 是否引入模型·引哪个 / 多模型链路。注意：这是**"路径/意图路由"**（route a *path* by meaning），**不是**单纯"选哪个 LLM"（那是 model-selection，只是其中一个分支）。**基于成熟开源，不自造。**

## 二、Landscape —— 按"做什么"分五类

### 类 A｜嵌入/语义路由器（无 LLM 调用，route *path* by meaning）
| 项目 | 规模 | 形态 | 备注 |
|---|---|---|---|
| **[aurelio-labs/semantic-router](https://github.com/aurelio-labs/semantic-router)** | 嵌入模型级(~0.02–0.3B) | **库** | 路线=示例话术集，按嵌入相似度即时匹配；快、确定、可扩展；嵌入模型可换（含本地）|
| **[vllm-project/semantic-router](https://github.com/vllm-project/semantic-router)** | mmBERT-32k ~0.3B | 服务(Rust+Go) | 8 个神经分类器(意图/越狱/PII/事实核查…)；生产级但**耦合 vLLM serving** |
| HF: `llm-semantic-router/mmbert32k-*` | ~0.3B | 模型 | 上者的分类器权重家族 |

## 三、关键判据（针对"入口解决方案路由"）
1. **路由目标是"解决方案路径"**(agent/搜索/邮件/模型/链路)而非仅"选模型" —— 类 A/D 契合，类 C 偏窄。
2. **~0.1B 量级 + 无 LLM 调用**(入口要快、每请求都过) —— 类 A(嵌入) 与类 B(微型) 最优。
3. **成熟度/社区**(不自造) —— semantic-router(aurelio) 最成熟通用；vLLM-SR 生产级但耦合。
4. **可替换/可拔插**(我们的核心诉求) —— 库(类 A) > 固定模型(类 B/C/D)：库的嵌入模型可换。
5. **本地/MLX 友好** —— semantic-router 可用**任意嵌入端点**；而 **oMLX 已暴露 `/v1/embeddings`**（U0 实测），天然对接。
6. **可扩展**(加一个解决方案=加一条路线) —— 类 A 最容易。

## 五、推荐与理由

### 首选：**aurelio-labs/semantic-router**（入口路径路由器）
**为什么**：
1. **结构最契合**——路线(routes)=解决方案(agent/搜索/邮件/模型/链路)，用示例话术定义，嵌入相似度即时匹配，正是"按用户输入路由到解决方案"。
2. **~0.1B + 无 LLM 调用**——入口每请求都过，必须快、确定、便宜；嵌入比较天然满足。
3. **最成熟通用的开源库**(不自造)，社区活跃。
4. **最可拔插**(我们的核心诉求)——它是**库**不是固定模型，底层嵌入模型可换(MiniLM/BGE-small ~0.02–0.1B，或**直接用 oMLX `/v1/embeddings`**，U0 已验证存在)。换嵌入=换 provider，接口不变。
5. **本地/MLX 友好 + 可扩展**——加一个解决方案=加一条 route，零重训。

### 二阶段（当路由到"工具/动作"分支时）：**端侧函数调用模型**
- semantic-router 决定**走哪条路径**；若路径=工具调用，再交 **xLAM-1b-fc-r / Hammer / Octopus-v2** 选**具体工具+参数**。二者互补、分层，非替代。**可后置**（先只做路径路由）。

### 观察/备选（不现在选）
- **Arch-Router-1.5B**：若将来要生成式 Domain+Action 路由(更细语义)可上，但 1.5B、固定模型、可拔插弱。
- **Supra-Router-51M**：最小、structured 输出很诱人，但训练集小、偏 model-difficulty、尚嫩——**观察其迭代**。
- **RouteLLM**：只做强/弱模型选择，不是路径路由——**不用于入口**（模型选择那层由 Agent24 ModelRouter 已覆盖）。

## 六、架构落点（呼应 08 图4 · 左 agent / 右 model）
```
用户输入 → [左] semantic-router(路线=解决方案) ──嵌入相似度──▶ 路径决策(agent/搜索/邮件/模型/链路)
                     │ 嵌入调用
                     ▼
              [右] 嵌入模型 = provider (oMLX /v1/embeddings 或 BGE-small)  ← 一物两面
```
- semantic-router **逻辑在左**(agent/入口)；它依赖的**嵌入模型是右侧 provider 池的一个 model**（可用 oMLX 的 `/v1/embeddings`）。与用户"左 agent、右 model、0.1B 两侧都算"的直觉完全对上。
- **实现归 Agent24**（前端用户交互入口，见 [09](./09-对Agent24的需求.md) 任务 ID-1）。
