# OpenAI-compatible model listing authentication

`GET /v1/models` forwards `IDORIS_OMLX_API_KEY` as a bearer token only when all of these configuration checks pass: provider family is `local`, provider locality is `loopback`, `version_pin` starts with `omlx@`, and the endpoint is HTTP(S) on a loopback IP or `localhost`. The card's provider id identifies its served model (for example, `Qwen3-0.6B-4bit`), so it does not identify the oMLX runtime. Credentials are never sent to cards with another runtime pin or to non-loopback endpoints. The shared upstream HTTP client disables redirects, so the token cannot be forwarded through a redirect.

An upstream `401` or `403` fails the entire listing with `502 upstream_error / upstream_authentication_failed`; successful cards are not returned as a misleading partial result. A configured credential that is non-UTF-8 or invalid in an Authorization header fails before contacting the affected oMLX upstream, with the same error envelope and an `invalid_authorization_header` log reason. Missing or empty credentials retain unauthenticated discovery. Other unavailable or malformed cards remain best-effort omissions. Logs contain only provider id, locality, and status or reason; they never contain the key or upstream body.
