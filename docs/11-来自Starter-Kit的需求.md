## 0. 背景：我们重复造了一层，应该并回来

泰国 Starter Kit（`iDoris-ai/iDoris-website` 仓库的 `products/`）为了让四个组件
（Voice / Documents / Creative / Assistant）能跑，**独立写了一层
`products/gateway/`**：意图路由、成本闸、审计留痕。

看到 [01 §3](./01-统一模型服务-架构设计.md) 之后可以确认：
**那和 iDoris Router 是同一层。** 我们不该并行维护两个。

**处置建议**：Starter Kit 侧的 Gateway **降级为 iDoris Router 的消费者**，
把已经写好并测过的规则**作为需求提上来**，而不是各写各的。

### 我们已经写出来、可以直接给的东西

| 东西 | 位置（website 仓库） | 状态 |
|:---|:---|:---|
| 路由策略引擎（三条不可破规则） | `products/gateway/routing.py` | 已建，**10 条变异测试**证明规则真的被兜住 |
| 审计留痕（只存元数据的边界） | `products/gateway/audit.py` | 已建，账期按曼谷时区 |
| 出网启动断言 | `products/assistant/egress_guard.py` | 已建，16 条变异 |

**这些是 Apache-2.0 同仓代码，iDoris 侧可以直接拿，不需要重写。**
如果 iDoris Router 采纳其中的规则，我们这边就删掉本地实现改为调用。

## ⚠️ R0｜多租户：这是最大的结构性错配，请先拍板

- **现状**：[01](./01-统一模型服务-架构设计.md) 把 iDoris 定位为
  **「个人 AI 网关」**，能力①「硬编码 loopback + 单用户」，
  「社区/城市端禁转发订阅」。
- **而泰国业务是托管多个客户**（`starter-kit/README.md` §5：
  「我们托管，不给客户自部署」——客户没有运维能力，Readiness 评分普遍 2–3 分）。
- **需求**：iDoris Router 需要**明确的多租户语义** ——
  至少是「每次调用带 `tenant`，用量、预算、审计按 tenant 隔离」。
- **为什么**：没有这个，Starter Kit 的四个组件就没法经 iDoris Router 走 ——
  我们会被迫继续维护那个平行实现，而两层路由策略并存，
  **迟早会在某个客户身上分叉**。
- **验收**：同一个 iDoris 实例，两个 tenant 的用量互不可见、预算互不影响、
  审计查 A 租户查不到 B 租户的任何一条。
- **注意合规边界不变**：多租户**只适用于能力②③（外部 API / 本地模型）**。
  能力①（订阅中转）的 loopback+单用户红线**不受本需求影响**，
  我们不要求、也不会用它转发订阅。

> **这一条不解决，下面所有条都悬空。** 建议优先拍板它属不属于 iDoris 的范围 ——
> 如果不属于，我们需要知道，好把 Gateway 保留为泰国业务的独立组件。

## R1｜预算硬停是**拒绝**，不是降级

- **需求**：租户预算用尽时，Router 必须**拒绝调用并返回明确错误**，
  不得自动降级到更便宜的档继续跑。
- **为什么**：[01 §3](./01-统一模型服务-架构设计.md) 的降级链是按
  「核心模型忙/OOM」触发的 —— 那是**技术性降级**，正确。
  但**预算是商业约束**，语义完全不同：
  客户设了上限就是不想再花钱，自动降级等于替客户做了「继续花，只是花得少些」的决定。
  一个「悄悄降级继续跑」的账单，客户看到时已经产生了。
- **我们的实现可参考**：`routing.py` 里预算硬停排在**任务匹配之前**，
  且有一条变异测试专门守它（「破坏预算硬停(超预算不再拒绝)」）。
- **验收**：预算耗尽 → 返回错误码，**不产生任何计费调用**；
  错误信息里说清「是预算不是故障」，否则客户会以为是我们服务坏了。

## R2｜隐私级别压过任务类型（顺序不能反）

- **需求**：`privacy=local_only`（对应我们的 `sensitivity=high`）的判定，
  必须排在「按意图选能力」**之前**。
- **为什么**：反过来写的话，「做 banner → 视觉模型（外部 API）」这条意图规则
  会先命中，隐私判定就没机会了。**顺序即语义。**
- **这一条 [09 R3](./09-对Agent24的需求.md) 已覆盖**（fail-closed），
  本条只是强调**它在 Router 内部的执行顺序**，不是新增语义。
- **验收**：一个 `privacy=local_only` 且意图明确指向外部能力的请求 →
  走本地或报错，**绝不出设备**；且这条要有测试，不是靠代码走查。

## R3｜每次路由决策必须可解释

- **需求**：Router 的每次决策返回里带一个 `reason` 字段，
  说清「为什么选了这个档」（隐私强制 / 预算 / 意图匹配 / 降级）。
- **为什么**：客户问「这次为什么用了贵的那个模型」，答不上来就没法收钱。
  更要紧的是**我们自己排查**：没有 reason，路由错了只能靠猜。
- **我们的实现可参考**：`routing.py` 每条决策都带 `reason`，
  且有变异测试守着「破坏可解释性(reason 置空)」。
- **验收**：任意一次调用的审计记录里都能读到非空 reason；
  reason 能区分上面四类原因，不是一句「routed」。

## R4｜审计只存元数据，**绝不存内容**

- **需求**：Router 的用量/审计层**不得记录 prompt、completion、
  或任何客户内容**；只存元数据（tenant / 组件 / 任务类型 / 档位 / 模型 /
  token 数 / 成本 / 延迟 / 状态 / reason）。
- **为什么**：**这是我们最不想承担的责任。**
  Router 是跨租户的集中组件 —— 一旦它存内容，它就成了一个
  「所有客户的会议记录、合同、客服对话」的集中数据库。
  泰国客户买我们的一个主要理由是「你的录音不出你的机器」，
  而一个存内容的网关会让那句话变成假的。
- **我们的实现可参考**：`audit.py` 用两道防线 ——
  frozen dataclass + **字段名黑名单闸门**（`prompt`/`content`/`messages`/
  `document`… 出现即拒绝写入）+ 单字段 500 字符上限
  （长文本出现在元数据里，本身就是「有人把内容塞进来了」的信号）。
- **验收**：故意往审计记录里塞一个 `prompt` 字段 → **写入被拒绝并报错**，
  不是静默丢弃。静默丢弃会让人以为它被存下来了。

## R5｜出网控制是**启动断言**，不是运行时警告

- **需求**：Router 进程启动时，若环境里存在任何会导致遥测外发的变量
  （`LANGSMITH_*` / `LANGCHAIN_*` 等），**拒绝启动**。
- **为什么**：我们实测过（website 仓库 `tools/verify/`）——
  LangGraph 不设变量时零出网，但设了 `LANGSMITH_TRACING=true`
  **确实会连** `api.smith.langchain.com`。**风险不在库，在部署配置。**
  而打警告没人看：一条 WARNING 出现在容器启动的前两秒、
  后面还有几百行输出，在真实运维里等于不存在。
  **启动不了人一定会看；数据流出去人不一定会知道。**
- **我们的实现可参考**：`products/assistant/egress_guard.py` ——
  **前缀扫描而非点名已知变量**（点名是失败开放：上游下个版本加个新变量名，
  清单不会自己长出来），认不出的一律拒绝，
  白名单每条必须写下豁免理由（由自检断言非空）。
- **验收**：设 `LANGSMITH_TRACING=true` 启动 Router → **进程退出非 0**；
  不设时正常启动；`LANGSMITH_TRACING=false` 也正常启动
  （关掉的开关是无害的 —— 否则运维为了起服务会去删配置管理里的整行）。

## R6｜账期时区必须显式，不能跟服务器走

- **需求**：用量按月聚合时，月份边界用**显式配置的时区**，
  不得使用服务器本地时区。
- **为什么**：这是我们**踩过的真坑**。原先月份边界用 `time.mktime()`（本地时区）
  而时间戳存的是 UTC epoch，同一笔「曼谷时间 10-01 06:00」的调用：
  服务器在 UTC 时算进 9 月账单，在曼谷时算进 10 月。
  **换台机器部署，客户账单就变，而且没有任何东西报错。**
  更难发现的是当时的测试也用 `mktime` 造时间戳，两边一起漂，
  所以在任何时区都自洽、永远是绿的。
- **验收**：同一批数据，在 `TZ=UTC` / `TZ=Asia/Bangkok` / `TZ=Pacific/Midway`
  三种环境下聚合，**月度结果必须完全一致**。
  （测试要真的切换进程时区跑，只在测试内部造时间戳抓不到这个 bug。）

## 非需求（明确不要 iDoris 做）

- **不要求 iDoris 承载业务语义**。Documents 的六个动作、Creative 的字数规则、
  Assistant 的审批队列，都留在 Starter Kit 侧 ——
  Router 只管「哪个模型、能不能调、记什么账」。
- **不要求 iDoris 提供前端**。`dev-plan.md` 已定前端不做；
  泰国客户的界面是 LINE。
- **不要求为多租户破坏能力①的合规红线**。订阅中转的 loopback+单用户限制
  我们不碰、也不用。
- **不要求 iDoris 立刻实现以上全部**。R0 拍板之后，
  其余六条按 iDoris 自己的 U0–U5 排期即可。

两种答案我们都能接着走，**但需要知道是哪一种**。
现在的状态是两套并行且没人写明关系，那是最坏的一种。
