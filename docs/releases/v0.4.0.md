# v0.4.0 发布说明

> 发布资产、tag 提交与 sha256 见 [GitHub Release v0.4.0](https://github.com/iDoris-ai/iDoris/releases/tag/v0.4.0)。

v0.4.0 是 iDoris 第一个可以被 **Agent24 桌面端一站式托管**（下载 → 运行 → 连接）的版本（[#588](https://github.com/iDoris-ai/iDoris/issues/588)）。同时，内存不够时的选择交给用户自己决定。从这个版本开始，CLI 使用 Developer ID 签名并经过 Apple 公证。

## 版本与范围

- Rust crate 和 `/health.version` 是 `0.4.0`。
- wire 契约升到 **`1.1.0`**。这一版只做了加法，1.0.x 的调用方可以照常使用。
- 范围是 v0.3.2 之后合入 `main` 的所有变更。

## 内存不够时，把选择交给用户（契约 1.1.0）

owner 2026-10-27 的决定：模型放不下时提示用户，给出两个选项——清理不用的模型，或者降级到小模型；1GB 余量保留，只有用户每次确认才能突破。

- **`GET /capabilities` 新增三个可选字段**（[#586](https://github.com/iDoris-ai/iDoris/pull/586)、[#593](https://github.com/iDoris-ai/iDoris/pull/593)、[#595](https://github.com/iDoris-ai/iDoris/pull/595)）：
  - `requires_eviction` 条目上有 `degraded_alternative`，内容是 `{id, capability, estimated_memory_gb, quant, reason}`，没有备选时为 `null`。它表示「不清理，改用这个现在就放得下的模型」。
  - `blocked` 条目上有 `degraded_alternatives`，是按能力列出的备选清单。
  - `headroom_breach_option`，内容是 `{id, quant, estimated_memory_gb, ctx_limit}`，表示「多用 1GB 余量就能换到的更优常驻模型」。整份快照里最多只有一个条目带这个字段，条目里的 id 唯一。
  - `reason` 是稳定代码 `fits_without_eviction`，不是给人看的文字。
- **运行时保留 1GB 余量**（[#587](https://github.com/iDoris-ai/iDoris/pull/587)）：只在设置了 `IDORIS_ALLOCATED_BUDGET_BYTES` 时生效。用户没有确认时，生命周期加载最多用到「额度 − 1GB」。
  - 在 `POST /v1/chat/completions` 上带 `X-iDoris-Headroom-Breach: confirmed`，表示用户确认这一次加载可以用到这 1GB。这个确认只对单次请求有效，iDoris 不会记住。
  - 某个模型只有用掉余量才放得下、而请求没带确认时，返回 `503 {"error":{"type":"headroom_confirmation_required","reason_code":"headroom_confirmation_required",…}}`。调用方应该去问用户，用户同意后带上这个头重试。
  - 另一个请求正在用不同的确认状态加载同一个模型时，返回 `503 reason_code=supervisor_busy`。稍后重试即可，不需要问用户。
  - **行为变化**：如果额度给得很紧，以前能直接加载的模型，现在可能需要用户确认。

## 一站式托管所需的 CLI 能力（#588 L1–L5）

- **`idoris setup omlx`**（[#590](https://github.com/iDoris-ai/iDoris/pull/590)、[#594](https://github.com/iDoris-ai/iDoris/pull/594)）：探测本机的 oMLX（能否连通、是否要认证、有哪些模型），然后生成组件目录，并用服务启动时同一个 loader 校验通过后才落盘。
  - API key 只通过 stdin 传入，只用于探测，不写进文件，也不回显。
  - 输出是 JSON。出错时有 11 个错误码，例如 `auth_required`、`model_not_found`、`write_failed`。
  - `--force` 的替换是全有或全无；中途失败会还原旧文件，还原不了时报错信息会写明备份文件名。
  - `--out-dir` 可以是 `.`（当前目录）。
- **`idoris key list` / `idoris key revoke <key_id>`**（[#589](https://github.com/iDoris-ai/iDoris/pull/589)、[#592](https://github.com/iDoris-ai/iDoris/pull/592)）：离线运行，输出 JSON，不会输出 secret 或 hash。
  - 吊销是幂等的。
  - 对正在运行的服务立即生效，因为服务每次请求都实时查库，没有缓存。
- **停止和单实例**（[#591](https://github.com/iDoris-ai/iDoris/pull/591)、[#594](https://github.com/iDoris-ai/iDoris/pull/594)）：
  - SIGTERM 和 SIGINT 走同一条优雅停机路径，总时限约 15 秒：优雅停机 10 秒，加上回收本地 runtime 子进程 5 秒。
  - `serve` 会对数据库的 canonical 路径加 OS 级独占锁。同一个数据库上已经有实例时，启动直接以**退出码 3** 失败。数据库的符号链接别名（包括首次启动前尚未指向实际文件的悬空链接）视为同一个数据库；硬链接别名不合并。
  - 退出码：0 表示正常，1 表示启动失败或停止失败，3 表示已在运行。
- **就绪判定**：只以 `/health` 为准，要求 `status=="ok"` 且进程存活。stdout 的输出不属于契约。

## 签名

`idoris` 用 `Developer ID Application: Huifeng Jiao (HYAP444FN9)` 签名，开启了 hardened runtime 和安全时间戳，并经过 Apple 公证（Accepted）。裸 Mach-O 不能 staple，所以第一次运行时需要联网核验一次票据。用 `curl` 或程序下载的文件没有 quarantine 标记。

## 已知限制

- 只提供 aarch64-apple-darwin 一个平台。
- 生命周期路径仍然拒绝 `temperature`。
- 没有升级迁移和备份命令。由 launcher 托管时，不支持自动升级，也不承诺回滚（M-IDL2 再做）。
- 内存额度不限制外部 resident 服务，也不限制实际 RSS。修改额度需要重启。

## 与 Agent24

Agent24 的一站式启动器设计见 [Agent24#1437](https://github.com/iDoris-ai/Agent24/pull/1437)。这个启动器只支持 v0.4.0 及以上版本，会校验 sha256 和签名的 TeamIdentifier。跨仓接口以 [接口规范](../interfaces/iDoris-Agent24-边界与接口规范.md)（修订 1.3）为准。
