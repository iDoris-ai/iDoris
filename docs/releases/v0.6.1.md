# v0.6.1 发布说明

> 发布资产、tag 提交与 sha256 见 [GitHub Release v0.6.1](https://github.com/iDoris-ai/iDoris/releases/tag/v0.6.1)。

v0.6.1 是 v0.6.0 之后的跟进修复版本，包含三项：oMLX key 管控加固（[#646](https://github.com/iDoris-ai/iDoris/issues/646)）、三本账账户历史压缩（[#643](https://github.com/iDoris-ai/iDoris/issues/643)）、生命周期测试加固与启动端口冲突校验（[#653](https://github.com/iDoris-ai/iDoris/issues/653)）。wire 契约保持 **`1.3.0`**，原因码集合不变。

## 版本与范围

- Rust crate（除 `idoris-compute-contracts` 外）和 `/health.version` 是 `0.6.1`；`contract_version` 仍是 `1.3.0`。
- 范围是 v0.6.0（`2903eb00`）之后合入 `main` 的所有变更：[#657](https://github.com/iDoris-ai/iDoris/pull/657)、[#658](https://github.com/iDoris-ai/iDoris/pull/658)、[#659](https://github.com/iDoris-ai/iDoris/pull/659)。
- 接口规范新增勘误十五（见规范文件头）。

## 行为变化（升级前请读）

- **`settings.json` 无法核验时本地 503**（#646）：oMLX 的 `settings.json` 持续不是合法 JSON 时，v0.6.0 当作没有 key 并匿名连接，现在返回本地 503（`upstream_unavailable`），不向上游发任何请求。同样返回 503 的还有：属主既不是 iDoris 的有效 UID 也不是 root、组或其他用户可写、macOS 上有 ACL 授予他人写权限、路径上的目录不可信。文案只列可能原因，不回显取值或 key。用环境变量 `IDORIS_OMLX_API_KEY` 可绕开；文件缺失或合法 JSON 里没有 key 时仍匿名连接，与 v0.6.0 相同。
- **外部 oMLX 每秒核验一次监听者**（#646）：签名结论绑定进程启动标识与内核给出的运行映像身份，进程换代或映像变化会触发重新核验（上游短暂显示 `external_replaced` 后自愈）。

- **启动拒绝与托管卡共用端口的本地运行时配置**（#653）：`IDORIS_LOCAL_RUNTIME_CONFIG` 指向的端口若与启动规划里真正托管的卡相同，启动失败，错误点名两张卡和端口。被规划排除的卡（如 LAN 卡）不占端口，托管引擎在别的端口也照常放行。
- **账本压缩**（#643）：新增迁移 `0006`（检查点表、`(account_id, entry_id)` 索引，不回填数据）。首次启动在写锁下建索引，大库上会多花一点时间。

## 账本压缩（#643）

- 准入、附加成本准入和超额结算在现有写事务里按账户推进检查点；每次请求每个账户最多折叠 1024 条分录，冷账户随后续请求逐步追平（20 万条约 196 次请求），请求路径上没有无界构建。
- 检查点保存分录水位、资金与花费累计、各额度桶剩余额；未关闭的预留及其后可能受影响的花费继续回放。读数与全量回放逐笔一致。
- 原始分录全部保留，供对账、补贴池账期和历史窗口回查。
- **已知限制**：一笔预留若在其后超过 1024 条分录才以超额结算，该账户的检查点不再推进，每次请求退回全量回放（结果仍正确）。这类账户继续按 v0.6.0 的 10 万笔历史建议控制容量。后续跟进见下。

## 测试加固（#653）

- 生命周期测试接入真实 Supervisor，覆盖监听消失、恢复、换代；watermark、迟到 202、oMLX 加载预算等用例改为能抓住原竞态的写法，每项都做过手工变异确认。

## 安全

oMLX key 管控加固（#646，威胁模型：另一个本机用户账号在窄窗口里抢到回环端口；同用户进程本就能读 key 文件，不在防护范围内）：

- 签名与每请求检查改用内核给出的运行映像身份（macOS：代码目录哈希 + Mach-O UUID，团队标识取自 `csops`；Linux：`/proc/<pid>/exe` 的设备与 inode），不再依赖可执行文件路径。磁盘上的文件被更新、替换或删除，不影响正在运行的合法引擎。
- 外部监听者的原生监视按签名通过时的进程代际绑定；自有引擎的退路核对所有权记录里的启动标识，回收的 PID 不会被授权。
- `settings.json` 拒绝符号链接文件，`.omlx` 可以是指向本人目录的链接，链接与目标目录都核对属主与写权限；macOS 上检查 ACL（跳过仅继承项）。
- 设置文件按 stat 复用解析结果，至多 1 秒，上游 401 时立即丢弃；同长度原地改写在 1 秒内生效。
- 仍存在的间隙：最终核验与 TCP 连接之间另一用户仍可能抢到端口；Unix domain socket 方案待确认 oMLX 支持后再评估。

## 已知限制与后续跟进

1. 账本检查点在「早期预留 + 超过一批之后的超额结算」时停滞（见上）；计划让切点覆盖批首被钉住的花费，或加后台空闲压缩。
2. [#656](https://github.com/iDoris-ai/iDoris/issues/656)：已发布架构的 `ledger_entries_insert_no_conflict` 触发器用 `-1` 作占位值，库里恰有序号 `-1` 的分录时后续写入会失败。生产写入路径不会产生显式序号，不受影响。

3. `~/.omlx` 是真实目录（不是链接）时，目录本身不做属主与 ACL 检查（v0.6.0 起即如此，文件本身的检查仍在）。
4. 供外部调用的同步解析函数（`resolve_for_endpoint` 等）仍把「无法核验」折成「没有 key」，工作区内没有生产调用方；后续改为返回 `Result`。
