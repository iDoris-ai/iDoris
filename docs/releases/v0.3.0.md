# v0.3.0 发布与 tenant key 迁移

v0.3.0 已发布：[正式 release](https://github.com/iDoris-ai/iDoris/releases/tag/v0.3.0)。
代码基线 `03c079c70611331a8c85a1666e32a75df6359d09`；本文承接旧 PR #487 的迁移说明。
实际安装与首次调用见[操作指南](../安装与首次调用-v0.3.0.md)。

## 版本与范围

Rust crate 和 `/health.version` 为 `0.3.0`，wire 契约为 `1.0.1`。
`/v1/inspect` 和 wire 1.1 的候选属于 M5，未包含在本次发布。
M4 包含 Event Log 查询、审计、就绪模型选路、只读 Admin v0 和显式 tenant key 绑定。
Admin 写接口未发布；tenant 部署监听仍限制为 loopback。

## Tenant key 迁移

1. 停止 Router，并备份实际使用的 SQLite 数据库。显式路径是 `IDORIS_DB_PATH`；
   未配置时按操作指南确认平台默认路径。不要把另一份新数据库误当作原数据库。
2. 启动新版本时，迁移 `0002` 为 key 增加可空的 `tenant_id`。
   旧 key 保留为未绑定；不会从 `owner` 或 `budget_ref` 推断租户。
3. tenant 模式要求显式绑定。按调用方原有权限签发新 key，发 key 命令与服务必须使用同一数据库。
   以下 spec 只授予 `fast` 和 `local_only`；按真实需要缩小或调整权限，不照抄扩大授权。

```json
{"owner":"agent24","tenant_id":"acme","allowed_privacy":["local_only"],"allowed_roles":["fast"]}
```

```bash
IDORIS_DB_PATH=/path/to/idoris.sqlite3 ./idoris key issue --spec-stdin < tenant-key.json
```

4. 将返回的 `secret` 交给对应调用方的凭证存储；不要提交命令输出或凭证到仓库。
   请求须带 `Authorization: Bearer …` 和唯一的 `X-iDoris-Tenant: acme`。
   header 与 key 的 tenant 绑定必须一致。验证新 key 成功后撤销旧 key，再切换调用方。

失效、过期或撤销 key 返回 401；格式错误/重复 tenant header 返回 400；
有格式正确 header 的未绑定或跨 tenant key 返回 403。成功缓存不免除后续请求鉴权。
Personal 模式保留未绑定旧 key 的兼容性；显式绑定 key 跨部署模式的授权上限修复正在
[PR #508](https://github.com/iDoris-ai/iDoris/pull/508) 审查，不能当作 v0.3.0 已包含的保护。

## 从 Tenant 切换到 Personal

Personal 的未绑定旧 key 兼容行为不是租户历史隔离机制。不要把曾用于 Tenant 的数据库直接用于 Personal。
切换时保留原 Tenant 数据库及备份，给 Personal 配置全新的数据库绝对路径并重新签发最小权限 key；
不要复制整份 Tenant 数据库或复用原未绑定 key。当前没有自动按租户拆库迁移命令。
PR #508 的显式绑定保护通过后，其他 tenant 的绑定 key 仍不能用于 Personal；绑定 `personal` 的 key
只接受缺省 header 或唯一且同为 `personal` 的 header。这不取消上述新数据库要求。

## 验收依据

正式发布已在实际 main 完成 Rust/TS、conformance 与归档 smoke 验收。
归档包含二进制和四个运行配置；更新后的 smoke 进一步隔离子进程 HOME/XDG/LOCALAPPDATA，
并检查 `/health.version` 与隔离数据库。新候选的测试不替代下一次发布时的实际 main 验收。

## 已合并的运行时与依赖修复

- Linux 本地运行时关停时，在回收直接子进程之前检查进程组中的存活成员。仅剩僵尸进程的组视为已清理，避免等待 PID 1 回收孤儿进程而超时；主线程为僵尸时仍检查同进程其他线程。非 Linux Unix 路径保持原有检查顺序。
- Linux `/proc/*/stat` 进程名按原始字节读取，避免合法的非 UTF-8 名称导致关停失败；仍拒绝畸形状态与组号元数据。
- `rustls` 从 `0.23.45` 升至 `0.23.46`，修复 RUSTSEC-2026-0346、0347、0348、0349。
- 这些运行时与依赖修复已通过独立审核和 CI，由 #501 合入 `main`（`e6e0fc176bb8ed7b9b5c1bb7a39b73536ec6a6ae`）；随后按父子顺序传播到 M4 尾部分支。不得依赖最后合并版本 PR 才解除上游 CI 阻塞。

## Event Log 数据库升级

- 首次启动会在事务内把规范的 v1 数据库升级为 v2，新增租户、事件类型和时间索引。已有事件保持不变，索引构建耗时与占用空间随历史规模增长。
- 只支持 v1 的旧二进制会拒绝已升级的 v2 数据库。回退前需要安排数据库处理，不能只替换二进制。
- 审计查询按时间索引选取候选记录，仍按完整历史中的 sequence 判断同类终态是否被取代。本地成功 Completed 事件用 `token_estimator: "conservative"` 标记既有预算估算口径。


## 限制

- Linux 存活成员检查依赖可读取且与当前 PID 命名空间一致的 `/proc`；受限可见性及改变 UID 的后代进程不属于本次已验证的常规启动场景。
- M5 的 REDACT 授权接线不属于本版本收尾范围；后续按用户逐次确认的决定实现。
