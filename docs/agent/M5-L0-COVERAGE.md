# M5 L0 检测覆盖范围（#445 分支）

本页只描述 #445 的实现，不把 main 或后续栈切片的能力视为本分支已提供。功能是否可用以实际合入版本和测试为准；零命中不构成内容安全证明。

## 当前覆盖与已知缺口

- 数字实体：裸值和用空格、tab、连字符连接的候选；手机号检查号段，居民身份证检查省码、日期和校验位（错误校验位降级），银行卡候选为 16–19 位且须通过 Luhn。会检查相邻数字段构成的子窗口，所以旁边的其他数字不必遮蔽有效实体。
- 不支持点、斜线作为数字分组分隔符。`6222.0212.3456.7894`、`6222/0212/3456/7894`、`110101.19900307.7379` 和斜线版本在无其他命中时可能 ALLOW。不得依赖 main 中的格式扩展。
- 本分支没有省码 83，不能宣称覆盖 `830000` 台湾居民居住证；8 位台胞证也未实现。
- HKID 支持现有紧贴号码的 ASCII/全角括号形式；`A123456 (3)` 等括号前带空格的形式未覆盖。不宣称所有畸形或混合括号均被接受。
- 归一化已处理 NBSP、全角空格、全角数字等既有映射，但不代表任意 Unicode 排版都能识别。邮箱仍是当前 ASCII 规则；其他证件/token 规则也不是全球格式全集。
- JSON 各值间使用 U+001F 硬边界，不能跨值拼实体。一个字符串内跨行拼接只支持**结构及校验位均正确的现代居民身份证**，并要求窗口覆盖整个数字组的起始/结束行段（不是物理行的所有数字）。手机号、15 位旧身份证、校验位错误的现代身份证和银行卡不跨换行拼接。明确的能力取舍：`138\n1234 5678`、`1101011990\n0307737X` 不再视为受支持的跨行实体；`1101051949\n1231002X` 仍为 S3。与单行的手机号/错误校验位降级行为不同，不把跨行号码零命中称为安全。
- 顶层 `input` 的整个子树中，任何非空全整数数组都算不可检查内容，无长度下限；混合数组、空数组/null 邻居或对象包装不会隐藏其内嵌套的非空全整数数组。平铺混合数组中零散的整数叶子不单独触发此规则。此启发式不扩展到工具 schema 或 metadata 等其他字段，也不宣称仅 embeddings 端点能带 `input`。

## 有意接受的银行卡表格取舍（G）

空格/tab/连字符连接的 16–19 位数字窗口通过 Luhn 后可能判为 `BankCard S3`，不限于四列或 16 位，更不是所有 tab 数字都会命中。例如 `6222\t0212\t3456\t7894` 和 `2023\t1203\t2024\t1305` 都被拦；不通过 Luhn 的对照行仍可 ALLOW。

评审在旧 head `0cd13ac` 的测量：四列各 1000–9999，单行 tab 命中约 9.98%，空格约 10.02%；12 行表分别为 150/200、142/200，50 行表为 198/200、200/200。不能把单行约一成写成整张表的概率。日期/单号/数量/金额等模板也可能命中，并不限于四个等宽数字列。这是多拦成本，不是泄漏。

影响：原声明 `any` 的请求会被钉成 `local_only`，只有远程候选时可能 503。**改 tab 为空格没有缓解效果**；不把换行当作普适绕过办法。结构化为各自独立的 JSON 值可避免跨值拼接，但一个值自身仍会接受检查。接受此取舍以保留 tab 分隔卡号检测；不承诺仅靠 Luhn 区分卡号和表格。

## 跨行误报矩阵

确定性种子 `0x44520261018`，8 种形状 × 5/12/50 行 × 每格 200 张表，共 4,800 张：单列 1..9999、单列 10..999、单列 1..99999、两列窄表（tab/空格）、三列小数表（tab/空格/CSV）。当前收窄规则的每格均为 **0/200**。测试逐格限制不超过 1%，不以总体平均掩盖某类错误；这只是此固定语料的读数，不是任意表格零误报保证。单行银行卡的 G 取舍仍独立存在。

## 验证边界

具名测试覆盖真实 tab 卡号、Luhn 合法数字行的 BankCard 分类、非 Luhn 对照、跨行窗口对齐及 `input` 混合子树。`/v1/inspect` 未提供 REDACT 同意接线时，S2 命中也 BLOCK。分类测试不替代真实出网验收，不表示整栈或 v0.3.1 已验收发布。
