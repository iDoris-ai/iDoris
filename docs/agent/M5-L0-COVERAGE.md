# M5 L0 检测覆盖范围

本页描述当前 M5 实现和验收范围，不替代 [总体规划](../iDoris-总体规划.md)。历史设计见 [三道硬闸 §1.7](../15-三道硬闸-隐私过滤-密钥凭证-模型切换.md#17-中文实体规则集调研核到标准原文可直接实现)。功能是否可用，以合入版本及其测试为准。

## 已实现的格式

| 类别 | 格式与边界 |
|---|---|
| 居民身份证 | 现有裸值、空格和连字符格式；新增单个 tab、点、斜线分隔的 `6/8/4`、`6/4/4/4` 分组，以及末位 `X` 对应形式。结构合法且校验有效为 S3；保留结构合法但校验错误时的降级规则。 |
| 台湾居民居住证 | 18 位 `830000` 形式进入居民身份证结构及校验规则；不是 8 位台胞证。 |
| 手机、银行卡 | 保留裸值及既有格式，新增单个 tab、点、斜线分隔的手机 `3/4/4`、国家码形式，以及四位一组的银行卡。有效实体子段不会因旁边还有不识别的数字而被整体丢弃。 |
| HKID | 保留原有号码形式；括号可为 ASCII 或全角成对括号，括号前可有一个 ASCII 空格。空格和括号都计入原始 UTF-16 span。 |
| 其他 token 规则 | 已实现的统一社会信用代码、护照、回乡证、车牌规则；这些规则不代表覆盖所有地区、所有排版或全部证件。 |
| 邮箱 | 仅当前 ASCII 规则；不覆盖 IDN 域名、全角 `＠` 和 punycode 顶级域。 |

允许实体形状的数字子段命中，意味着包含有效号码形状的数字表也可能被拦截。例如 `1111.6222.0212.3456.7894.2222` 中间的有效银行卡会命中。这是避免相邻数字遮蔽实体的保守取舍，不承诺零误报。

## 尚未覆盖的输入

- **8 位台胞证尚未实现**，留待后续规则及误报边界验收，不称本轮已补齐历史 §1.7 的全部证件。
- `_`、`,` 分隔仍不在本轮数字格式规则内，例如 `320102_19851231_0045`、`6222,0212,3456,7894`、`138_1234_5678`。
- 连续分隔符、NBSP、全角空格、全角数字、带空格的连字符形式不由此切片统一归一化；后续 normalization 切片必须在更新后的栈顶单独验收。
- 不支持的任意分组形状不等同于已支持的手机或卡号格式。车牌小写/连字符变体、部分转义文件名边界也尚未全部覆盖。

**在 `any`、允许远程且没有其他规则命中时，上述未覆盖输入可能使 `/v1/inspect` 返回 `ALLOW`。** 不得把零命中解释为“所有隐私均已排除”；`local_only` 或禁止远程的上下文仍返回 `BLOCK`。

## HTTP 验收与授权

接线测试使用真实 Router、虚拟 key 和 `POST /v1/inspect`，分别检查动作、敏感度、实体类别及原始 UTF-16 span。分组身份证、相邻数字、四条 Gate-1 短邻居均有具名测试；移除格式分隔符支持必须使对应测试失败。

此 HTTP 切片尚未提供 REDACT 同意接线，因此 S2 命中也返回 `BLOCK`。将来开放 REDACT 时必须遵守已决定的本地控制台逐次确认，当前切片不提供调用方自声明同意或长期授权。

这些测试证明分类端点行为，不代替后续 chat/协议端点的真实出网字节验收，也不代表 M5 已整体验收或发布。
