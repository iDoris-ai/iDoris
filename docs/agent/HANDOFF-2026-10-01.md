## 3. 待修阻塞项

### #48 · M1 — oMLX "先分配后校验"会让账本漏记内存
- 位置：`crates/idoris-backend/src/supervisor.rs`（`resolve_load_failure`）+
  `crates/idoris-upstream/src/omlx/mod.rs:189-263`（`load` / `pin` / `check_not_unexpectedly_pinned`）
- 问题：`POST /v1/models/{id}/load` 已经成功（内存已真实占用），之后 `pin()` 或
  `GET /v1/models/status` 失败返回 `Err`，supervisor 把槽位落成 `Stopped`，`used_gb` 变 0，
  且 `Stopped` 下 `unload()` 短路，内存收不回来。
- 处方：区分"确认未分配"和"不确定/已分配"两类错误（新增 `BackendError` 变体，或在
  `OmlxAdapter::load` 校验失败时先自行 unload），后者和 `AdapterTimedOut` 一样走
  `best_effort_release`；在 `RuntimeAdapter` trait 文档里写明"`Err` ⇒ 未分配或已释放"；
  补 wiremock 集成测试：POST load 200 + GET status 503 / `pinned:true` 漂移。

### #48 · M2 — 只按输入计费的卡被误判为"确定免费"，绕过预算
- 位置：`crates/idoris-router/src/components.rs:107`（`resident_card_is_provably_free`）+
  `crates/idoris-router/src/budget.rs`
- 问题：用空 prompt 探测费用，`{input_per_m:5, output_per_m:0}` 算出 0，于是进了不接预算的直连转发路径。
- 处方：直接判 `cost.input_per_m == 0.0 && cost.output_per_m == 0.0`；加回归测试
  `{5,0}` → `PaidResidentUnsupported`，以及 `{0/0, x/0, 0/x, x/x, NaN}` 表格测试。
