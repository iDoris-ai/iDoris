## 6. 工作方式与踩过的坑（必读）

### 6.1 B 机流水线（ab-codex）

工具源码：`/Users/jason/Dev/tools/ab-codex/`（README 有完整说明）。A 端命令 `abx`：

- `abx enqueue idoris <名字> <prompt 文件> <read-only|write>`：给 B 排任务；`abx status`：看队列、正在跑的任务和 steward 日志；`abx install-b`：部署脚本更新（**不会打断正在跑的任务**，worker 在两个任务之间自动换新版本）。
- B 上的 steward 每 5 分钟巡检：凡是 base 在 `feat/` 下、当前提交还没评审过的 PR，自动排 Codex 评审。
- **自动合并的条件（全部满足才合）**：Codex 批准、CI 全绿、没有冲突，并且 **prdaemon（`clestons`）在当前提交上批准**。prdaemon 还没对当前提交表态时，每个提交只 @ 它一次，PR 进入等待清单，steward 每轮复查；prdaemon 或 Codex 要求修改、CI 红、有冲突时，自动排修复任务。release PR（base 是 main）**不自动合并**，人工处理。
- Codex 额度用完或模型满载：任务放回队列，全体暂停（额度 30 分钟、满载 5 分钟）后重试，不会丢任务；额度提前恢复时删掉 B 上的 `~/ab-codex/state/quota-paused-until` 即可。

### 6.2 发版流程（v0.1.1、v0.1.2 都这么走）

1. 功能分支 → release PR 进 main → 在 PR 下留言 `@clestons 请审阅` → prdaemon 批准 + CI 绿后合并（`gh pr merge --merge --match-head-commit <sha>`）。
2. **单独开一个 PR 把 7 个 crate 的版本号升到新版本**（含 `Cargo.lock`），并在 `progress.md` 记一笔；同样经 prdaemon 批准后合并。**不升版本号就打 tag，发版冒烟会拦下**（它核对 `/health` 的 version 与 tag）。
3. 在 main 的合并提交上打 `vX.Y.Z` 并推送 → release workflow 构建、冒烟、发布。
4. 自己下载发布包实测一遍，Release 说明里写清已知问题。

### 6.3 已经付出过代价的坑

- **叠加 PR 被自动关闭，内容丢失**：PR A 的 base 是 PR B 的分支，B 合并时删了分支，GitHub 就会自动关闭 A。#188、#191、#197 都这样丢过（#197 从未被评审）。automerge 现在会先把叠加 PR 改指上一级分支；**手动合并时也要先改指再删分支**。排查方法：查已关闭未合并的 PR 里有没有 `base_ref_deleted` 事件。
- **zsh 冒号修饰符**：A、B 都是 zsh。`"$base:refs/..."` 会被解析成 `$base:r` + `efs/...`，`$B:crates/...` 会变成 `$B:c`。变量后面接冒号一律写 `${var}:`。B 的 steward 曾因此一整天拉不到 PR。
- **nullglob 下不要 `ls glob`**：无匹配时等于裸 `ls`，会列出当前目录。B 的 worker 曾因此把 `~/Applications` 当任务搬走。用数组 `arr=($dir/*.job(N))`。
- **prdaemon 的「要求修改」被绕过**：#187、#207 曾在 prdaemon 要求修改后被直接合并（已用 §6.1 的门禁堵上）。prdaemon 的意见有实质价值，不要绕。
- **同步 main 时的 FU 编号冲突**：多条功能分支各自往 `tasks.md` 末尾追加 FU，会撞号（openai-compat 与 release-packaging 都用了 FU-200 起）。新开功能分支时先查 main 上已用到的编号。
- **把关注点混进同步 PR**：评审同步 PR 时可能暴露 main 上已有的问题（如 #211 的竞态），修复会跟着该功能分支走，不会立刻进 main；需要尽快修的应从 main 单独开分支。

### 6.4 门禁与规则

- Rust：`cargo fmt --check`、`cargo clippy --all-targets --features idoris-tenancy/test-bins,idoris-tenancy/mutation-test-hooks -- -D warnings`、同 features 的 `cargo test`、`cargo deny check advisories bans licenses sources`；改到路由行为加跑 `bash scripts/conformance-rust.sh`。
- TS：`pnpm lint && pnpm typecheck && pnpm check:contract-drift && pnpm build && pnpm test && pnpm conformance`。**一律用 pnpm**。
- 单个 task PR ≤300 行，带承重回归测试并做变异验证；超限要在 PR 里说明并由维护者接受例外。
- 评审：Tier 1 = Codex；不可用时本地模型 + prdaemon，并注明档位。**不使用 Copilot**。
- 合并方式统一 merge commit；用户已授权「批准即合并、打 tag 发版、清理已合并分支」，无需再问。
