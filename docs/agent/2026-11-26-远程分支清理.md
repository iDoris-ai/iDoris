# 远程分支清理记录（2026-11-26）

v0.6.1 发版后，`origin` 上有 67 个未合入 `main` 的分支，全部是 2026-10-01 至 10-24 留下的，没有一个有打开的 PR。owner 同意按下面的方式处理。

## 处理原则

- **删除 59 个**：
  - PR 已关闭的旧叠放分支（identity-keys、event-log、gate-two、inspect、resilience 等系列）。关闭时的审计评论写明内容已以别的形式进入 `main`、被后续 PR 取代，或 owner 决定不做，多处注明「不要重放」。
  - 夜班 / 云端 agent / 值守 / 交接 / 验收 / 旧发版准备分支（`baton/*`、`claude/*`、`jhfnetboy/*`、`ops/*`、`handoff/*`、`test/cloud-*`、`prep/*`、`release/v0.3.0` 等）。代码部分在 `main` 上已有等价提交或已被取代，其余是过程记录。
- **保留 8 个**：多引擎相关、没做完的 runtime 工作改名为 `archive/runtime-*` 留作参考，原有的 `archive/rust-parity-07-rule-wiring` 不动。这些分支基于 10 月中旬的代码，v0.6.0 已重写引擎管理与引擎抽象，**不能直接合入**。将来做多引擎（LM Studio、Ollama、vLLM…）时只取思路，基于当时的 `main` 重写，走正常 PR 流程。

## 恢复方法

下表记录了每个分支删除时的提交 sha。需要找回时：`git fetch origin <sha> && git branch <名字> <sha>`。PR 已关闭的分支，提交一般也保留在 `refs/pull/<编号>/head`，但有 3 个例外：PR 关闭后分支又推过提交，表里的 sha 比 PR head 新（见删除表的标注）。这 3 个 sha 已各打一个附注 tag `archive/pr<编号>-tail` 保住，用 `git fetch origin tag archive/pr481-tail` 之类取回；没有 PR 的分支，只能靠 sha 找回，GitHub 可能在垃圾回收后不再提供，所以如果本地 clone 里还有这些提交，也可以从本地恢复。
