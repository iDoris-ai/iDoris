# R9：规范修订 1.2 整合与 v0.3.1 最小集成提案

日期：2026-10-15。状态：**OWNER REVIEW PENDING**，尚无双方最终确认或 owner 拍板。本页是协商记录，不是第二份规范；唯一规范权威见 [边界与接口规范](../iDoris-Agent24-边界与接口规范.md)。

## 提议范围

把 R0–R8 已接受的角色/动作授权、local_only、四类凭证、Admin 只读和 FD 秘密边界整合为一份正文。文档修订 1.2 与 runtime `contract_version=1.0.1` 分开；本轮不升 wire version、不新增 schema，不宣称 v0.3.1 已实现。Agent24 的短 consumer pointer 应链接该规范与固定版本，并反向链接其 HW-TIERS/ADR-036；由 Agent24 owner 在另一仓修改，本轮不代改。

拟议首片只交付 local_only 数据面，独立于配对 launcher：明确 URL 和数据 key → HTTP role 请求 → iDoris 运维绑定真实模型 → locality/Record-Id 校验。第二 any provider/key 延后，D-6 的完整两把 key 设计不撤销。无 launcher 时 Admin 卡仍 unavailable；完整 M4 readiness 仍需独立组合验收，不以文档替代。

## 实现差距与验收门

准确实际/候选映射以规范 §4 为准：I0=`03c079c`、A0=`6072fd37`；#507=`a232f83`、#508=`1c9c592`、#510=`bbf99ec` 和 budget=`a078b033` 都未合并。Agent24 #964/#966 仍为 OPEN 提案，不把 `usable_bytes` 当作现成 `llm_allocated_bytes` API。

待实现/确认：HTTP 运维 role map（含 auto）及失败关闭、实际模型 load/chat 一致；key ceiling 与鉴权前事件；allocated 整数字节进入执行 ledger；Agent24 独占 provider/凭证桥/locality 绊线；max_tokens 与 timeout 兼容；未来 capabilities 字段和 readiness 均仍为目标。不得为了凑验收发明新 wire version、动态预算 HTTP API 或当前不存在的 ready 输出。

验收应以真实 Rust Router + 确定性本地后端 fixture，分别验证推荐与实际并发 load、local_only 失败零外呼、缺 key/错 key/角色越权、真实模型身份、CLI/Desktop/module 参数及错误处理；Admin 单独验证匿名 FD intake 与 trusted producer。最后由 owner 在干净 macOS arm64 环境用已校验发布包和预备权重做真实成功调用/加载释放；无下载/付费 fixture 不能代替真机组合验收。本轮仅做文档/源码核对，不运行这些测试，不声明 M5 可启动。
